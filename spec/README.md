# The `jaah.ai` ACP extension, version 1

An agent that speaks the [Agent Client Protocol](https://agentclientprotocol.com) (ACP) runs on Jaah as
it is. This extension adds what a Jaah task needs beyond ACP: settling the task, asking a human,
fetching credentials, filing follow-up work. It follows ACP's
[extensibility rules](https://agentclientprotocol.com/protocol/extensibility): capability negotiation in
`initialize`, a namespaced key under `_meta`, and underscore-prefixed custom methods.

The machine-readable contract is [`jaah-extension.json`](jaah-extension.json): every method's name,
params JSON Schema and result, and the capability schema. This page explains it; the JSON wins where
they differ.

## Roles

- **Client**: the Jaah node's ACP host. It launches the agent over stdio, sends the prompt, and serves
  the extension methods.
- **Agent**: your program. It implements ACP's agent side and may call the extension's methods.

## Negotiation

The client advertises the extension in `initialize`, under `clientCapabilities._meta["jaah.ai"]`:

```json
{
  "protocolVersion": 1,
  "clientCapabilities": {
    "_meta": {
      "jaah.ai": { "version": 1, "methods": ["_jaah.ai/task/complete", "_jaah.ai/credential/get"] }
    }
  }
}
```

- `version` is this document's version, `1`. An agent that does not support the offered version treats
  the extension as absent.
- `methods` lists the methods this client serves for this run. An agent MUST NOT call a method that is
  not listed: the list depends on the task (a persona's licence, whether project memory is on).
- No `_meta["jaah.ai"]` means a plain ACP client. The agent MUST still run there (the `acp-core`
  conformance profile) and simply never calls the extension.

The agent advertises nothing back: calling a method is the agent's only act.

`session/new` MAY carry `_meta["jaah.ai"]` with run context (for example the task id). It is
informational; the agent never sends a task id, because the client knows which task the run is.

## Methods

Every method is an agent → client JSON-RPC request. A daemon verb `noun.verb_name` is the ACP method
`_jaah.ai/noun/verb_name`, the same verb behind Jaah's MCP tools and its `jaah-call` command.

- **Params**: the method's `params` schema in the JSON. Unknown keys are refused.
- **Result**: a JSON object, the control plane's answer.
- **Errors**: JSON-RPC errors. `-32601`: the method is not served. `-32000` with message
  `refused: <reason>`: the call was refused (invalid params included) — fix it, never resend it as is.
  `-32000` with message `unavailable`: the control plane was not reached — the call may be retried as
  sent. A client MAY answer invalid params with `-32602` before forwarding them.

## Rules every agent follows

1. **Settle once, last.** One accepted `task/complete` or `task/fail` per session, sent before the
   `session/prompt` response that ends the turn. A settle that was refused, or answered `settled: false`,
   did not settle: fix what it names and send it again. Settling ends the run; nothing the agent sends
   afterwards is recorded.
2. **No secret in the environment.** A credential comes from `credential/get` and reaches a tool as a
   file the tool reads (mode `0600`), never an environment variable. Never log a credential's value.
3. **No identity claims.** The client knows which task and session the agent serves; no method takes a
   task id.
4. **Plain ACP still works.** Without the capability the agent runs as an ordinary ACP agent.

## Conformance

`conformance/` in this SDK checks an agent against this page; the SDK's [README](../README.md) shows
how to run it.

| Profile | Checks |
|---|---|
| `acp-core` | `initialize` negotiates ACP v1; `session/new` returns a session; `session/prompt` ends with a stop reason after at least one `session/update` naming the session; an unknown extension method gets `-32601`; no `_jaah.ai/*` call without the capability |
| `jaah-extension` | `acp-core`, then a run advertising every method and one advertising only `task/complete`: in each, every call is an advertised method with schema-valid params, and exactly one settle is accepted, inside the turn |
